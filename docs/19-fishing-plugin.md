# 19. `@rpg/plugin-fishing` — 釣り大会（プラグイン）と、そのために core に足した「プラグインの待機」

> ステータス：**デモまで実装済み**（デモ「港町の釣り大会」。core に足した部品は「プラグインの待機」だけ）。この文書は、方針と、作ったものの実装メモ。

竿を振り、あたりを待ち、バーの中に魚を入れ続けて巻き上げる**ミニゲーム**と、釣った魚の**図鑑**、制限時間つきの**釣り大会**を、プラグインとして作る。
18（不思議のダンジョン）が「状態を持つ・毎フレーム呼ぶコマンドで回す」の実例だったのに対して、こちらは「**プラグインが画面と入力をしばらく預かる**」実例（ミニゲーム・独自の画面）。

## 方針

18 と同じ。

1. **釣りそのものはプラグインにする。** `plugins/fishing` は `@rpg/plugin-api` だけに依存する（第三者のプラグインと同じ立場）。魚・竿・エサの抽選、あたりと巻き上げの状態機械、ライバルと順位、図鑑、描画はすべてプラグインに置く。
2. **core にはジャンルを問わない部品だけを足す。** 足す基準は 18 と同じ：釣り以外の作品でも使い道があり、釣り抜きの小さなテストで使い道を示せること。
3. **詰まった所だけ足す。** 先に core を変えずに試作した。詰まったのは 1 か所（下）だけだった。

## core に足したもの：`wait: plugin`（プラグインの待機）

**詰まった所**：ミニゲームは、数秒〜数十秒のあいだ、毎フレーム入力（決定ボタンを押している間・離した間）を読み、その場で状態を更新し、終わったら次のコマンドへ進む。
コマンドの `resume`（待機中に毎フレーム呼ばれ、`CommandCtx.input` が読める）は 03 にもともとあったので、仕組みとしては足りていた。足りなかったのは **待機の種類**：`WaitState` は組み込みの種類（`frames` / `message` / `choice` / `move` / `battle` / `shop` / `transfer` / `child`）だけで、プラグインが「自分の待機」を名乗れない。`frames` で代用すると、(1) 既定の解除（フレームを数えて解除）が混ざる、(2) セーブされた待機の意味がわからなくなる、(3) プラグインを外したセーブを読むと勝手にフレームを数え出す。

- **`WaitState` に `{ kind: "plugin"; name: string }` を足した**（`name` はプラグイン名）。`CommandControl` の `{ kind: "wait", wait: { kind: "plugin", name } }` を返すと、`resume` が `next` を返すまで `pc` が進まない。
- **解除は `resume` が決める。** `resume` を持たない（プラグインが読み込まれていない・コマンドが消えた）ときは、既定の解除（`defaultResume`）が**警告を出して解除する**ので、詰まらない。
- **セーブ**：`snapshot` の検証スキーマ（`waitSchema`）に `plugin` を足した。`SNAPSHOT_VERSION` は上げない（待機の種類が増えただけで、これまでのセーブは変換なしで読める）。古いビルドが `plugin` の待機の入ったセーブを読むと、検証で弾かれる（18 の `pluginState` と同じ）。
- **ほかの部品は変わらない**：待機中（`normal` のインタプリタが動いている間）は、プレイヤーは歩けず・メニューも開けない（既存の仕様。`handleInput`）。ミニゲーム中にセーブはできないが、ミニゲームの前後（図鑑・持ち物・変数）は普通にセーブされる。
- **ダンジョン・釣り以外の使い道**：パズルのミニゲーム（鍵開け・ハッキング）、独自の画面（図鑑・ステータス・クラフト）、タイミング入力（QTE）。
- **テスト**：`run.test.ts`（`resume` で入力を読んで解除する・`resume` が無いと警告して解除する）、`snapshot.test.ts`（待機の途中で JSON を往復しても同じ状態に戻る）。プラグインを使わないゲームの状態・リプレイのハッシュは変わらない（新しい種類を足しただけ）。

## 非責務

- 釣りの**画面そのものを core のシーンにすること**：ミニゲームの表示は、マップシーンの上に `projection.after("map")` で描く（マップが見えたままで、ウキが水面に浮かぶ）。専用のシーン（プラグインが `update` / `project` を持つ）は、全画面の独自画面が必要になったとき（カードゲームなど）に、`wait: plugin` と同じ基準で検討する。
- 魚が泳ぐ姿・竿の絵・釣りのアニメーション（スプライトの追加）。表示は文字と四角（`gauge`）だけで、アセットを持たない。
- 釣りの BGM・効果音（`plugin` Effect で足せる）。

## プラグインの中身

| 部分 | 内容 |
|---|---|
| 設定（`params`） | 竿（アイテム・当たり判定の広さ）、エサ（アイテム・あたりの早さ・手ごわい魚の出やすさ）、魚（アイテム・大きさの範囲・点数・出やすさ・釣れる場所・難しさ 1〜5）、大会（制限時間・ライバルと実力・順位ごとの賞金・トロフィー）、結果を残す変数の名前 |
| 状態 | `pluginState.fishing`（`model.ts`）：図鑑（魚ごとの数と最大）、大会（点数・釣果・最大）、今の 1 回（`cast`）、画面（図鑑・結果発表）。セーブに含まれる |
| コマンド | `plugin:fishing/Cast { spot }`（竿を振る。`wait: plugin`）、`Start`（大会を始める）、`Watch`（制限時間を見張る。並列イベント）、`Result`（結果発表。`wait: plugin`）、`Album`（図鑑。`wait: plugin`） |
| 表示 | `projection.after("map")`（`hud.ts`）：大会の点数、ウキと波紋、「！」、巻き上げのバー、結果、つり手帳、結果発表 |
| エディタ | ひな形「釣り場」「つり手帳（図鑑）」「大会の進行役」と、診断（設定・アイテムの参照・釣り場の種類・進行役の有無） |

### 竿を振る → 釣れるまで（`fish.ts` の `stepCast`。純関数）

1. **`wait`**：あたりまでの時間は 90〜260 フレーム × エサの `bite`（エサなしは 1.4 倍）。キャンセルでやめる（エサは戻る）。**決定ボタンを早く押すと逃げられる**（`early`）。
2. **`bite`**：「！」が出て、40 フレームのあいだに決定ボタンで合わせる。逃すと `missed`。かかる魚は、釣れる場所の魚から重みつきで選び、**エサの `rare` が大きいほど、難しい魚ほど出やすい**（重み × `rare ^ ((難しさ − 1) / 2)`。難しさ 1 は影響なし）。大きさは範囲の中で小さい方に偏る。
3. **`reel`**：横長のバーの上で、魚（黄色の四角）が動く先へ向かって動き、ときどき動く先を選び直す。決定ボタンを**押している間は当たり判定（緑）が右へ、離すと左へ**慣性つきで動く。魚が当たり判定の中にいる間は巻き上げ量が増え、外にいると減る。1 になれば `caught`、0 になれば `lost`。魚が難しいほど、速く・頻繁に動き、外にいるときの減りも大きい。
4. **`done`**：結果を 110 フレーム見せる（24 フレームたってから決定ボタンで飛ばせる）。やめたとき（`quit`）は見せずに終わる。

結果の反映（持ち物・図鑑・大会の点数・変数）は、巻き上げが終わったそのフレーム（`applyOutcome`）。結果の表示中にセーブされても、反映ずみ。

**調整**（`fish.test.ts`）：反応が約 130ms 遅れる操作で、基本の竿（0.2）は小物（イワシ）だけ、ふつうの竿（0.28）はスズキまで 9 割以上・マダイ 6 割以上・マグロは 9 割未満、良い竿（0.36）はマグロも 9 割以上釣れる。つまり、**竿を買い替える意味がある**。何もしないとほとんど逃げられる。

### 釣り大会

- **始まり**：受付のイベントが参加費を払って `Start` を呼ぶ。点数を 0 にして、core のタイマー（`state.timers`。`ControlTimer` と同じ。右上に自動で出る。メニューを開いている間は止まる）を制限時間で動かす。
- **点数**：基本の点数 ×（大きさに応じて 0.6〜1.4 倍）。ながぐつは 0 点。
- **終わり**：マップの**大会の進行役**（並列イベント）が毎フレーム `Watch` を呼ぶ。タイマーが止まり、ほかのイベント・文章が動いていなければ、変数 `event` を 1 にする → 自動実行ページが鐘のセリフを出し、`Result` を呼ぶ（ダンジョンの `Tick` / `Finish` と同じ形）。釣っている最中に時間が来たら、その 1 匹は最後まで釣れて、そのあとで終わる。
- **結果発表**：ライバルの点数は、めやす（`skill`）の 7〜13 割（`ctx.rng`。同じシード・同じ入力なら同じ結果）。順位は点数の高い順で、**同点ならプレイヤーが上**。賞金・トロフィー（1 位だけ）を渡し、変数（順位・点数・優勝回数）を残す。順位表は `wait: plugin` の画面で、決定ボタンで閉じる。
- **進行は変数とスイッチで**：プラグインは「大会に出ているか」をスイッチに持たない。イベントが自分で `sw_tournament` を立てて、受付や NPC のセリフを分ける（プラグインの `tournament` 状態は、点数のため）。

## 不変条件

1. 同じ状態・同じ乱数・同じ入力なら、同じ結果（`stepCast` は純関数で、乱数は引数）。
2. かかる魚は、その釣り場で釣れる魚だけ。大きさは範囲の中。
3. 巻き上げの途中、魚の位置・当たり判定・巻き上げ量は常に 0〜1 で、当たり判定は端からはみ出さない。必ず決着がつく（釣れる・逃げられる）。
4. 結果発表の順位は、点数の高い順（同点はプレイヤーが上）。賞金は順位の表から（足りない順位は 0）。
5. プラグインを読み込まないプロジェクトのリプレイは、`wait: plugin` を足す前と同じ結果になる（14 の不変条件 1 と同じ）。
6. `packages/core` に `fishing` という名前の型・状態・コマンドが無い（`wait: plugin` はジャンルを問わない名前）。

## 実装メモ

- **ミニゲームの 1 フレームは `resume`**：`Cast` の `run` が `cast` 状態（`pluginState.fishing.cast`）を作って `wait: plugin` で待ち、`resume` が毎フレーム `stepCast` を 1 回呼んで状態を書き直す。決定ボタンを押しているかは `input.pressed`、押した瞬間は `input.triggered`。`run`（コマンドが始まったフレーム）の入力は読まないので、釣り場を決定ボタンで起動した、そのボタンがあたりの合図と混ざらない。
- **表示は状態から**：`fishingHud` は `cast` の `phase` を見て描く（ウキは、プレイヤーの向きの 2 マス先。あたりのあいだは沈んで揺れる）。表示用の状態を別に持たないので、セーブして読み直しても、その場面から再開できる。結果の表示は画面の上寄り（プレイヤーとウキを隠さない）。
- **釣り場はマップのイベント**：水のマスの上に置いた `action` イベント（`plugin:fishing/Cast { spot }`）。水は通れないので、水辺に立って水に向かって決定ボタンを押すと起動する。釣り場の種類（`spot`）は文字列で、魚の `spots` と突き合わせる（診断が、釣れる魚の無い種類を警告する）。
- **魚・竿・エサ・トロフィーはデータベースのアイテム**：釣ると `party.items` に入るので、売る（`ShopProcessing { canSell }`）・持ち物の一覧・図鑑に出ない魚の価値は、ふつうのアイテムのまま。竿・トロフィーは `kind: "key"`（売れない）。竿は持っているだけで効く（持っている中で一番広いもの）。エサは振るたびに 1 つ使う（持っている中で一番良いもの）。
- **core のタイマーを使う**：制限時間の表示と数え方を作らず、`state.timers`（`ControlTimer`）をそのまま使った。メニュー・ショップ・戦闘のあいだは止まる（`handleTick`）。
- **ダンジョンとの違い**：18 は、並列イベントが毎フレーム呼ぶ `Tick` で世界を進める（プレイヤーは普通に動ける）。釣りは、プレイヤーを止めて 1 つのコマンドが入力を預かる（`wait: plugin`）。どちらも状態は `pluginState`、表示は `projection.after`。
- **作っていないもの**：魚や竿の絵・効果音、場所ごとの天気・時間帯、エサの選択（持っている中で一番良いものを自動で使う）、大会のライバルの実際の釣り（点数だけを乱数で決める）、ミニゲーム中のセーブ。
