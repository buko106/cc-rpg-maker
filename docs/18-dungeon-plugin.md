# 18. `@rpg/plugin-dungeon` — 不思議のダンジョン（プラグイン）と、そのために core に足す汎用の部品

> ステータス：**デモまで実装済み**（D0〜D5 を、下の「実装メモ」の形で作った。core に足した部品は ① だけ）。この文書は、方針と、作る順番を決めるためのもの。実装した内容と、設計から変えた点は末尾の「実装メモ」。

入るたびに地形が変わり、プレイヤーが 1 歩動くと敵も 1 歩動く、「不思議のダンジョン」型のゲームを作れるようにする。

## 方針

1. **ダンジョンそのものはプラグインにする。** `plugins/dungeon` は `@rpg/plugin-api` だけに依存し、第三者のプラグインと同じ立場で作る（`plugin-samples` と同じ）。
   フロアの生成・敵の行動・満腹度・ターン・ダンジョンの戦闘は、すべてプラグインに置く。
2. **core にはジャンルを問わない部品だけを足す。** `core` に「ダンジョン」「フロア」「満腹度」といった概念を持ち込まない。
   core に足す部品は、どれも次の基準を満たすこと：**ダンジョン以外の作品でも使い道があり、ダンジョン抜きの小さなテストかデモで、その使い道を示せる**。
3. **詰まった所だけ足す。** 先に core を変えずにプラグインを試作し、実際に行き詰まった所の部品だけを 1 つずつ足す（1 部品 = 1 PR）。

## 非責務

- 斜め（8 方向）の移動。core の `Direction` と入力・タッチパッド・キャラの絵（4 方向）にまで手が入るので、ここでは扱わない。必要になったら別に検討する。
  プラグインの内部では位置の差を `(dx, dy)` で持ち、あとで斜めを足せるようにしておく。
- 仲間（パーティでの探索）・道具の未識別・店・罠の種類の作り込み。土台ができてから、すべてプラグインの中で足す。

## 依存が許されるパッケージ

`@rpg/plugin-api` のみ（`tools/dependency-rules.cjs` に `"plugin-dungeon": ["plugin-api"]` を足す）。
`player` と `editor-ui` は、`plugin-samples` と同じように、このプラグインを同梱する。

## 今のエンジンで使えるもの

| 必要なもの | 使えるもの |
|---|---|
| フロアの地形の書き換え | `ChangeMapTile` と同じ仕組み（`GameState.mapTiles`）。通行の判定・描画・カメラは、どれも `currentMap()` が返す、書き換え後の `MapData` を見る |
| 決定論的な乱数 | `CommandCtx.rng`。同じシード・同じ入力なら、同じフロアになる |
| 追跡の経路 | `chaseDirection`（BFS の最短経路の最初の 1 歩） |
| ぶつかって攻撃・目の前を攻撃 | 通常プライオリティの `touch` トリガ（突き当たる）と `action` トリガ（決定ボタン）。敵のイベントのページから、プラグインのコマンドを呼ぶ |
| 敵・道具のデータ | `database.enemies` / `database.items`、ダメージ計算 `calcDamage` |
| HUD・戦闘ログ・ミニマップ | `projection.after("map", …)` |
| ダンジョンの設定 | `system.plugins` の `params` |
| 置くイベントのひな形 | `editor.eventTemplate` |
| 中断セーブ | `system.menuSave`、セーブ画面を開くコマンド（`SaveGame`） |

## core に足す汎用の部品（候補）

いずれも「必要と分かったら足す」候補。足すときは、該当するパッケージの文書（02 / 03 / 14）にも書き足す。

### ① プラグインの保存領域

- `GameState.pluginState?: Record<string, JsonValue>`。キーはプラグイン名、値は JSON にできる値。セーブに含める（`SNAPSHOT_VERSION` を 2 に上げ、`snapshotMigrations` を足す）。
- プラグインは自分の名前のキーだけを読み書きする。書き込み口は `CommandResult.state` か、`plugin-api` に用意する小さな関数（`withPluginState(state, name, value)` など）。
- 14 の「プラグインが書き換えてよいのは `interpreters[].locals` と `variables` だけ」という取り決めを、この領域にまで広げる。
- **ダンジョン以外の使い道**：クエストの記録、図鑑、クラフト。今はプラグインが状態を置ける場所が数値の変数しかない。
- **ダンジョンでの使い道**：何階か・敵の HP と位置・落ちている道具・満腹度・ターン数・歩いた場所の記録。

### ② イベントの複製と消去

- `SpawnEvent`：ひな形にするイベント（`{ mapId, eventId }`）を、今のマップの指定した位置に複製する。実行時にできたイベントはセーブに含め、マップを出たら消す。
- `EraseEvent`：今のマップにいる間だけ、イベントを消す（ツクールの「イベントの一時消去」）。
- ページの条件・トリガ・移動ルートは、ひな形のものをそのまま使う。
- **ダンジョン以外の使い道**：弾、召喚、落とし物、増える敵、使い捨ての演出用キャラ。
- **ダンジョンでの使い道**：フロアごとに数の違う敵と道具を置き、倒したり拾ったりしたら消す。
  これが無いあいだは、ひな形のマップに「空き」のイベントを多めに置いておき、`SetEventLocation` とセルフスイッチで出し入れしてしのぐ。

### ③ 歩数に合わせた移動

- 移動ルート（`moveRoute`）に設定を足す：`pace: "frames"`（今まで通り。既定）| `"playerStep"`（プレイヤーが 1 歩歩くたびに、ルートを 1 歩だけ進める）。
- プレイヤーが歩く・向きを変えるだけ・足踏みする、のどれで「1 歩」と数えるかは、この部品を作るときに決める。
- **ダンジョン以外の使い道**：倉庫番風の謎解き、忍び込みの見張り、チェスのようなパズル。
- **ダンジョンでの使い道**：敵が、プレイヤーの 1 歩に 1 歩で動く（ターン制）。

### ④ プラグインのフック

- `host.hooks.afterPlayerStep((state, ctx) => state)`：プレイヤーの 1 歩が終わったときに、状態を書き換える口。乱数は `ctx.rng` を使う（決定論を保つ）。
- 必要になれば、ほかの節目（場所移動の後、など）も同じ形で足す。
- **ダンジョン以外の使い道**：毒の床、歩くと進む時間、ゲームの中の時計。
- **ダンジョンでの使い道**：満腹度を減らす・HP を回復する・敵を行動させる（③で足りないとき。行動の早さが違う敵など）。

### 足さないもの

- フロアの生成は、今ある `mapTiles` に書き込む。1 フロアを丸ごと書き換えるとセーブや処理が重すぎると分かったときだけ、「レイヤを丸ごと差し替える」部品を、①〜④ と同じ基準で検討する。
- ダンジョン専用の戦闘画面は作らない。戦闘は今ある戦闘（`BattleProcessing`）を使わず、プラグインのコマンドがマップの上で計算し、結果を戦闘ログに出す。
- `plugin-api` から再エクスポートする関数（`calcDamage`・`chaseDirection` など）は、プラグインが使うと分かった純関数だけにする。

## プラグインの中身

| 部分 | 内容 |
|---|---|
| 設定（`params`） | 階数、ひな形のマップ、床・壁・階段のタイル番号、階の範囲ごとの「出る敵の表」と「落ちている道具の表」（重みつき）、満腹度、入るときにレベルを戻すか |
| コマンド | `Enter`（ダンジョンに入る）、`NextFloor`（階段）、`Attack`（敵のイベントのページから呼ぶ）、`PickUp`（道具のイベントから呼ぶ）など。code は `plugin:dungeon/…` |
| フロアの生成 | マップをおよそ 3×3 の区画に分け、区画ごとに部屋か通路の中継点を置き、隣どうしを L 字の通路でつなぐ（全域木に、ループになる辺を少し足す）。そのあと階段・プレイヤー・道具・敵を部屋に置く。シードは `rng` から作る |
| 敵の行動 | プレイヤーが見えたら（同じ部屋か、通路で隣のマス）`chaseDirection` で追い、隣にいたら攻撃する。見えなければ、部屋の出口へ向かうか、通路をまっすぐ進む |
| 表示 | `projection.after("map")` で、階・HP・満腹度・戦闘ログ・ミニマップを描く |
| エディタ | `eventTemplate` で「ダンジョンの入口」「階段」などのひな形を出す |

## 不変条件

1. 同じシードとダンジョンの設定から、同じフロアができる（生成は純関数）。
2. 生成したフロアでは、すべての床がつながっていて、プレイヤーの位置から階段にたどり着ける。物（プレイヤー・階段・敵・道具）は同じマスに重ならない。
3. プラグインを読み込まないプロジェクトのリプレイは、①〜④ を足す前と同じ結果になる（14 の不変条件 1 と同じ）。
4. core に `dungeon` という名前の型・状態・コマンドが無い（`packages/core` を検索して見つからない）。

## テスト要件

- 生成：fast-check で、不変条件 1・2 を、シードと設定を変えて確かめる。
- ①〜④ の各部品：その部品を足す PR の中で、ダンジョンを使わない単体テストかリプレイを足す。
- プラグイン：ひな形のマップと入力列から、階段を降りる・敵を倒す・道具を拾うリプレイを作り、ゴールデンテストにする。
- デモ：`tools/make-dungeon-demo.mjs` で小さなダンジョン（5〜10 階）を作り、他のデモと同じように、フィクスチャのテストと E2E を足す。

## 実装メモ（D0〜D5 を作ってわかったこと）
**方針の 3 は「詰まった所だけ足す」だった。** 先に core を変えずに作って、詰まったのは ① だけ（セーブに入る置き場）だった。②③④ は足していない。

- **core に足したもの**：① `GameState.pluginState`（02・14 の実装メモ）。`SNAPSHOT_VERSION` は上げなかった（省略できる項目を足しただけなので、これまでのセーブは変換なしで読める。バージョンを上げると、使わないゲームのセーブまで古いビルドで読めなくなる）。
- **敵・落ちている物にマップのイベントを使わない**（②「イベントの複製と消去」が要らなかった）：敵・物・歩いた場所はすべて `pluginState.dungeon`（`model.ts`）に持ち、`projection.after("map")` が `FrameSpec` に直接描く（敵・物は、タイルの層と、キャラクターの層の間。歩いていないマスのタイルは 0 にして描かない）。敵と物は決まった数のイベントに縛られず、セーブに丸ごと入る。マップは「町」と「フロアのひな形」の 2 枚だけ。
- **ターンは、並列イベントが毎フレーム呼ぶコマンドで回す**（③「歩数に合わせた移動」・④「`afterPlayerStep`」が要らなかった）：フロアのひな形のコントローラ（`ev_dungeon`）の並列ページが、毎フレーム `plugin:dungeon/Tick` を呼ぶ。`Tick` は、プレイヤーの位置が前のフレームから変わっていたら「1 歩」、決定ボタンが押されたら「その場で 1 ターン」と数えて、敵の行動・満腹度・回復を進める（`turn.ts`）。敵のいるマスへ進もうとしたら、プレイヤーを元のマスに戻して、半歩だけ踏み出して戻る動き（`realX/realY` を半歩ずらして `moving: true`）にする：ぶつかって攻撃に見え、押しっぱなしでも 4 フレームに 1 回しか攻撃しない。階段は、状態を書き換えてその場で次の階に替える（フロアの切り替えにフラッシュの Effect だけ）。
- **`Tick` の中から `TransferPlayer` を呼べない**：場所移動は元のマップの並列イベントのインタプリタを終わらせるので、移動を待っている `Tick` 自身も消えて、明転が終わらない（14）。倒れたとき・宝を取ったときは、`Tick` が変数（`vars.event` = 1 / 2）を立て、コントローラの自動実行ページ（文章 → `plugin:dungeon/Finish`）が町へ戻す。
- **地形の書き換え**：`Enter` / 階段のたびに、フロアの `mapTiles[floorMap]` を丸ごと入れ替える（床・階段・壁の正面だけを書き、岩はひな形の初期の状態なので書かない）。キャッシュは書き換えの参照で効くので、毎フレームのコストは無い。39×27 で、セーブに入る書き換えは 300〜500 マス。
- **乱数**：フロアの生成は、`ctx.rng` ではなく、`seed:階` から決まる独立の乱数（`rng.ts` の mulberry32）。同じシード・階・設定なら必ず同じフロアになり、セーブには `grid` を持つので、アルゴリズムを変えても保存済みの階は壊れない。ダメージ・ドロップ・敵のうろうろは `ctx.rng` を使うので、リプレイは再現する。
- **コマンド**（code は `plugin:dungeon/…`）：`Enter`（ダンジョンに入る。新しいシードで 1 階を作り、レベル 1・HP 全回復・持ち物を `startItems` にして、`TransferPlayer` を `call` で呼ぶ）、`Tick`（上記）、`Finish { result: "dead" | "clear" }`（倒れた：持ち物と、入ってから拾ったお金を失う／宝：ごほうび。どちらも HP 全回復・最深階・結果・クリア回数の変数を更新して `pluginState.dungeon` を `null` にし、町へ戻す）。
- **フロアの生成**（`generate.ts`）：区画 3×3（大きさは 8×6 以上）に、部屋（確率 0.78。最低 4 つ）か中継点を置き、ランダムなプリム法の全域木に 2 割のループを足して、L 字の通路でつなぐ。開始位置と階段は別の部屋（階段は、開始位置から遠い部屋 2 つのうちどちらか）。最後の階は階段の代わりに宝。`fast-check` で、不変条件 1・2（同じシードで同じフロア／床がすべてつながり、階段に着ける／外周は岩／物が重ならない）を確かめている（`generate.test.ts`）。
- **敵の行動**：プレイヤーから歩いて `sight` 歩以内なら、プレイヤーを起点にした 1 回の幅優先探索の距離を下って近づく（隣にいれば攻撃。ほかの敵・プレイヤーのマスには入らない）。それより遠ければ、6 割の確率でランダムに 1 マス。`act` が `fast` なら 1 ターンに 2 回、`slow` なら 1 ターンおき。ダメージは `攻撃力 − 防御力/2 ± 1`（最低 1）。
- **表示**（`hud.ts`）：左上に階・レベル・HP・満腹度、右上にミニマップ（歩いた床・階段・見えている敵・自分）、左下にログ（最新 3 行）、ダメージなどの数字（浮かんで消える）、階に着いた直後の見出し。敵の動きは、1 ターンの始めの位置から 8 フレームで補間する。
- **エディタ**（`templates.ts`）：ひな形「ダンジョンの入口」「ダンジョンのコントローラ」（3 ページ。変数名は `system.plugins` の設定から読む）と、診断（設定が不正・ひな形のマップが無い／大きさが違う／コントローラが無い・敵や物がデータベースに無い）。
- **メニューのアイテムの使用は、ターンを進めない**（くすり草を飲んでも敵は動かない）。ダンジョンの外と同じ、メニューの仕組みをそのまま使うため。必要になったら、メニューを閉じたときに 1 ターン進める口を足す。
- **作っていないもの**：罠・仲間・道具の未識別・店・斜め移動（非責務のとおり）。階段は確認なしで降りる。「中断セーブ」は専用の仕組みを作らず、ふつうのメニューのセーブ/ロードが、`pluginState` とフロアの `mapTiles` ごと戻す（`plugin.test.ts`）。
- **テスト**：`plugins/dungeon`（生成・配置の性質、ターンの計算の単体、HUD、ひな形と診断、デモを実際のランタイムで動かす：入る・歩く・攻撃・休む・階段・倒れる・宝・セーブとロード・同じ入力で同じ結果、階段へ進むだけの単純なボットがどこまで潜れるか）、`apps/player/src/dungeon-fixture.test.ts`（デモの定義：プラグインの設定がデータベース・タイルセット・スプライトシートと食い違っていないこと・ひな形のマップの形）、`e2e/dungeon.spec.ts`（ブラウザで洞窟に入って 1 階を歩く）。**不変条件 3**（プラグインを読み込まないゲームのリプレイは変わらない）は、`pluginState` の無い状態が変わらないことと、「村のデモに dungeon プラグインを読み込んでも状態のハッシュが同じ」で確かめる。**不変条件 4**：`packages/core` に `dungeon` は無い（`pluginState` だけ）。
